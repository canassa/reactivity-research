# 2026-10-16: the digest prototype (compiled dirty checking)

## Done

- `frameworks/digest/`: a runtime of about 120 lines (bindings, conditional nodes, keyed lists,
  delegated events, mount and dispose), a thin adapter, and a plain Vite 8.3.4 build (rolldown
  1.2.14, the same as Solid) with no plugin and hidden source maps. Track: prototype.
- `scenarios/dashboard/digest.js`: one factory per widget kind present, one data row per
  instance, rules partially evaluated into data (a field rule becomes one regex; an amount
  format becomes prefix, decimals and suffix), metric and phrase code only for kinds a summary
  reads, `receive` branches only for events the app can get.
- `./rr check` passes at sizes 1, 2, 4, 8, 16, 32, 64 and 128, seeds 1 to 3. A scratch fuzzer
  ran 2,000–3,000 random user actions and external events per app (including dispose and
  remount) and compared each step with the reference: 0 failures. The fuzzer was checked by
  planting a bug, and it caught it.
- Measured (runs.json sizes and seeds): N=1 median 1,027 B br; all sizes 2,115 + 24.3 B/widget;
  N ≥ 16 3,130 + 18.6 B/widget. Solid: 6,583, 8,293 + 35.8, 9,652 + 28.1.

## Learned

- **Brotli makes repeated inline code nearly free.** Shared helpers (`model`, `ids`, `drop`,
  `prop`) cost more in the runtime than they saved in the app: +15 B at N=1 and +14 B baseline.
  Other byte-level ideas moved totals by ±10 B, which is noise.
- **The slope is the data.** The instance rows' strings alone grow by 14.4 B/widget. The rows
  grow by 19.1 B/widget and the whole app by 18.6. Structure left to save: a few bytes per
  widget.
- **Vite's modulepreload polyfill is about 270 B br** of every Vite app here: a quarter of
  digest's N=1. It was kept for parity.
- **Cache the last written value instead of reading the DOM back.** That is what makes the
  amount rule and the caret work without special cases.
- **The serve-page comparison collapses whitespace.** A todo `add` that forgot to trim would
  still pass the check, so the fuzzer's planted bug had to be a visible one.
- **Typing `1e2` into an amount already at 100** leaves `1e2` in the input. Solid does the same.
  The fuzzer avoids that input.
