# 2026-10-29: React 19 added

- **Setup** (`frameworks/react/`, README there): create-vite 9.3.3's `react` template (React and
  ReactDOM 19.3.1, Vite 8.3.5, @vitejs/plugin-react 6.1.2), and its `react-compiler` template as
  the `compiler=on` option (babel-plugin-react-compiler 1.0.0). Same source for both: plain React,
  no manual `memo`/`useMemo`/`useCallback`.
- **Adapter:** `createRoot` and `flushSync` for mount and dispatch; external events are a
  subscription the app opens in a `useEffect`. `settled()` flushes sync work, then waits one
  `MessageChannel` task, because updates from the app's own timers (routed-app) render in React's
  scheduler task, which `flushSync` does not reach. Dispose removes the delegated listeners
  `createRoot` leaves on the root and the document (undocumented detail, as for Solid and Marko).
- **Harness fix:** the serve panel and `./rr work` typed with `input.value = …`, which React's
  value tracker swallows (no `onChange`). They now use the prototype's setter, as real typing
  does; every other framework's check still passes.
- **Emitters**, all six scenarios, mirroring the Solid emitters' structure: state lifted into
  `App` (`useState` and a context; `useReducer` in derived-graph), updater functions, keyed
  `.map`, controlled inputs, a local draft for number inputs that hold no number. Same-task
  pass: actions on gone controls are no-ops through guards in the updaters (routed-app route)
  and a ref on the modal (a second confirm in one task).
- **Checks:** big-table, big-component and routed-app pass at sizes 1/16/64/256, seeds 1–3,
  compiler off and on. derived-graph fails only at N=256 seed 1 in the same-task pass (top-k rows
  replaced after "serverItems, then snapshot"); Solid and vanilla fail identically, so it is the
  harness case, not React. unique-components: the checks that finished pass; the run was killed
  for low memory before n=256 (seeds 1–2 off, 3 on) and `--lists none`.

## Results so far

| scenario | React | React + compiler | Solid |
|---|---|---|---|
| shared-components, N ≥ 16 | 60.9 KB + 28.3 B/widget | 63.1 KB + 49.5 | 9.6 KB + 28.2 |
| big-component, all sizes | 59.5 KB + 68.4 B/field | 62.8 KB + 83.2 (R² 0.63) | 7.7 KB + 91.9 |

- React's runtime is ~58.3 KB brotli, flat; the baseline is almost all runtime.
- Plain React's per-widget slope matches Solid's on the dashboard and is lower on the form: JSX
  compiles to `jsx()` calls, with no template strings or per-binding effects.
- **The compiler roughly doubles the slope** (memo cache slots and guards per component).
- **Dead end found:** React Compiler 1.0 overflows its stack ("Maximum call stack size exceeded",
  a `PipelineError`) on the 3,385-line big-component form at N=256 and, with the default
  `panicThreshold`, leaves the component uncompiled without failing the build. That point ships
  plain React, hence the poor fit. N=128 (1,660 lines) compiles.
- big-table: no `memo` on rows (js-framework-benchmark's React entries use it); it changes CPU,
  not size, and the compiler variant is the memoized one.
