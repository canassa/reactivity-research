# 2026-10-29: React 19 added

- **Setup** (`frameworks/react/`, README there): create-vite 9.3.3's `react` template (React and
  ReactDOM 19.3.1, Vite 8.3.5, @vitejs/plugin-react 6.1.2), and its `react-compiler` template as
  the `compiler=on` option (babel-plugin-react-compiler 1.0.0). Same source for both: plain React,
  no manual `memo`/`useMemo`/`useCallback`.
- **Adapter:** `createRoot` and `flushSync` for mount and dispatch; external events are a
  subscription the app opens in a `useEffect`. `settled()` flushes sync work, then waits one
  `MessageChannel` task, because updates from the app's own timers (routed-app) render in React's
  scheduler task, which `flushSync` does not reach. Dispose removes the delegated listeners
  `createRoot` leaves on the root and the document (undocumented detail, as for Solid and Marko).
- **Harness fix:** the serve panel and `./rr work` typed with `input.value = …`, which React's
  value tracker swallows (no `onChange`). They now use the prototype's setter, as real typing
  does; every other framework's check still passes.
- **Emitters**, all six scenarios, mirroring the Solid emitters' structure: state lifted into
  `App` (`useState` and a context; `useReducer` in derived-graph), updater functions, keyed
  `.map`, controlled inputs, a local draft for number inputs that hold no number. Same-task
  pass: actions on gone controls are no-ops through guards in the updaters (routed-app route)
  and a ref on the modal (a second confirm in one task).
- **Checks:** every emitter passes at sizes 1/16/64/256, seeds 1–3, compiler off and on
  (unique-components also at `--lists none`). derived-graph fails only at N=256 seed 1 in the
  same-task pass (top-k rows replaced after "serverItems, then snapshot"); Solid and vanilla fail
  identically, so it is a harness case, not React. Some N=256 checks hit the 10-minute limit while
  the load average was ~20 and passed alone.
- **Cleanup:** the low-memory kill of a batch run left two headless Chromes running (reparented to
  systemd) and seven `rr-chrome-*` profiles in `/tmp`, a tmpfs (~1 GB of RAM between them);
  `harness/chrome.js` only removes a profile when its check exits normally. Removed by hand.

## Results

Fits from `./rr report` (brotli, total), per unit of N; N ≥ steady size where the scenario has one.

| scenario | React | React + compiler | Solid | vanilla |
|---|---|---|---|---|
| shared-components, N ≥ 16 | 60.9 KB + 28.3 | 63.1 KB + 49.5 | 9.6 KB + 28.2 | – |
| unique-components | 60.3 KB + 158.0 | 62.1 KB + 399.1 | 8.7 KB + 230.9 | – |
| big-component | 59.5 KB + 68.4 | 62.8 KB + 83.2 (R² 0.63) | 7.7 KB + 91.9 | – |
| big-table, N ≥ 4 | 61.6 KB + 214.2 | 63.7 KB + 270.6 | 10.1 KB + 225.7 | 4.2 KB + 255.0 |
| routed-app | 61.9 KB + 309.3 | 65.5 KB + 788.2 | 13.1 KB + 430.3 | 4.2 KB + 451.0 |
| derived-graph, N ≥ 16 | 60.7 KB + 71.4 | 70.4 KB + 61.3 (R² 0.36) | 9.4 KB + 123.3 | 2.9 KB + 142.4 |

- React's runtime is ~58.3 KB brotli, flat; the baseline is almost all runtime.
- Plain React's slope matches Solid's on the dashboard and is lower everywhere else, and lower
  than vanilla's where vanilla is measured: JSX compiles to `jsx()` calls, with no template
  strings, per-binding effects or hand-written DOM updates. React pays once, in its runtime.
- **The compiler steepens the slope in every scenario where it compiles every point**, from
  1.3× (big-table) to 2.5× (unique-components, routed-app): memo cache slots and their guards per
  component.
- **Dead end found:** React Compiler 1.0 overflows its stack ("Maximum call stack size exceeded",
  a `PipelineError`) on a component of ~3,400 lines or more (the big-component form, 3,385 lines,
  and the derived-graph sheet, 3,581, both at N=256) and, with the default `panicThreshold`,
  leaves it uncompiled without failing the build. Those points ship plain React, hence the poor
  fits. N=128 (1,660 and 1,871 lines) compiles.
- big-table: no `memo` on rows (js-framework-benchmark's React entries use it); it changes CPU,
  not size, and the compiler variant is the memoized one.
